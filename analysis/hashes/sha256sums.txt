# SHA-256 checksums

Reference checksums for the artifacts this project talks about. Vendor
binaries are **not** distributed here — only their hashes, so that anyone
holding a dump of their own unit can confirm it is the same artifact the
documentation describes.

## Vendor reference artifact

Factory FIP partition, MTD3 slice, 2,097,152 bytes, taken from a JIDU6801:

```
cd204b85467f2f2f209ee41d290f582078ed8c59d34b07d0fa50e0a0cd6b208f  factory_fip_6801.bin
```

SHA-256 of the installed `kernel` volume on that unit:

```
ebae7d5e99ea3d8fd9627ed5a72d75ab2f1ae62016b798fc4836f21d4900e237  (contents of /dev/ubi0_0)
```

`rootfs_data` is deliberately not checksummed — it is the device's mutable
state and differs per unit by definition.

## Reproducing the build

Image names produced by the device definition in `openwrt/`:

```
openwrt-mediatek-filogic-jiorouter_ax6000-jidu6801-initramfs-kernel.bin
openwrt-mediatek-filogic-jiorouter_ax6000-jidu6801-squashfs-sysupgrade.bin
```

Note there is no `.itb`: the build emits a bare arm64 `Image` with a separate
DTB, while the stock bootloader is a FIT loader. See
`docs/openwrt-port.md` §6.2.

Builds are not bit-reproducible across toolchain or snapshot revisions.
For reference, checksums from this verified tree build (commit `8dafdff` on
`r0-57072d9`) as recorded in `bin/targets/mediatek/filogic/sha256sums`:
